# Database-Olap-Benchmark

# Database Performance and Scalability Analysis for OLAP Workloads

This repository contains the source code and experimental tools used in the undergraduate thesis research entitled:

**"Database Performance and Scalability Analysis for OLAP Workloads (Case Study: Satu Data Universitas Hasanuddin)"**

The research analyzes and compares the performance and scalability of three Database Management Systems (DBMS): PostgreSQL, ClickHouse, and MongoDB, using OLAP (Online Analytical Processing) workloads.

## 1. Research Overview

The experiments involve three DBMS implementations with three dataset scales:

- SF0.1
- SF0.5
- SF1.0

The repository provides scripts for database loading, benchmark execution, data validation, result equivalence checking, table storage information extraction, and database storage and query diagnostics.

## 3. Repository Components

### 3.1 Database Loader

The `loader/` directory contains scripts for loading synthetic datasets into the three DBMS.

Each DBMS has three loading scripts corresponding to the dataset scales used in the experiments.

**PostgreSQL**
- `load_postgresql_sf0.1.py`
- `load_postgresql_sf0.5.py`
- `load_postgresql_sf1.py`

**ClickHouse**
- `load_clickhouse_sf0.1.py`
- `load_clickhouse_sf0.5.py`
- `load_clickhouse_sf1.py`

**MongoDB**
- `load_mongodb_sf0.1.py`
- `load_mongodb_sf0.5.py`
- `load_mongodb_sf1.py`

### 3.2 Benchmark Runner

The `benchmark/` directory contains scripts for executing and validating benchmark experiments.

- **`benchmark_runner.py`**  
  Executes the benchmark queries and collects the experimental results for each DBMS.

- **`check_result.py`**  
  Checks the benchmark results generated by the benchmark runner for each DBMS.

- **`validate_equivalence.py`**  
  Compares query results across PostgreSQL, ClickHouse, and MongoDB to evaluate whether the results are equivalent.

### 3.3 Database Schema

The `schema/` directory contains the database schema definitions.

- **`postgresql.sql`** — PostgreSQL table definitions.
- **`clickhouse.sql`** — ClickHouse table definitions.

### 3.4 Data Validation

The `data_validation.py` script validates the loaded datasets by checking whether the data stored in each DBMS matches the source dataset.

### 3.5 Table Storage Exporter

The `table_storage.py` script collects and exports table information into CSV files, including the number of rows and columns in tables across the three DBMS.

### 3.6 Diagnostic and Storage Collector

The `diagnostic_and_storage_collector.py` script collects database storage and index information and performs query diagnostics for the experimental queries.

## 4. Experimental Workflow

The general experimental workflow is organized as follows:

1. Prepare the synthetic datasets for each experimental scale.
2. Create the database structures using the provided schema definitions and database loading scripts.
3. Load the datasets into PostgreSQL, ClickHouse, and MongoDB.
4. Validate the loaded data using `data_validation.py`.
5. Execute the benchmark queries using `benchmark_runner.py`.
6. Check the benchmark results using `check_result.py`.
7. Compare query result equivalence across DBMS using `validate_equivalence.py`.
8. Collect table information using `table_storage.py`.
9. Collect database storage, index, and query diagnostic information using `diagnostic_and_storage_collector.py`.
